# Install-Skills.ps1: test cases

Script: `..\Install-Skills.ps1`. The destination is `%USERPROFILE%\.copilot\skills` (read from `$env:USERPROFILE`) and the repo root is the folder the script sits in. That makes a safe sandbox possible without changing the script: copy `Install-Skills.ps1` into a temporary repo with a few fixture skill folders (each with a `SKILL.md`), set `$env:USERPROFILE` to a temporary folder in the process that runs it, and answer the per-skill prompts by piping `y` or `n` into `powershell -File`. Never run the cases against the real user skills folder. Run 2026-11-01 in such a sandbox (the real skills folder had the same 35 files before and after). The toolkit cases (I-24 onward) also need the sandbox `$env:USERPROFILE` (they create `.copilot\toolkits` there) and use `-ToolkitBaseUrl <folder>` with small fixture toolkit repos (each a git repo with a `VERSION` file and a stub `scripts\agent\Build-Toolkit.ps1`), so no network and no real toolkit is touched. The one exception is I-37, run against the real folders on purpose.

## Findings

- Destination-only files are left in place by default and removed only with `-Prune` (added 2026-11-13). Removal is confined to the skill's own destination folder and covered by the per-skill confirmation (skipped with `-Force`). `-Prune -Force` together delete without any prompt; that combination was run only in the sandbox on a rerun with nothing to delete.
- Toolkits (2026-11-13): a toolkit is cloned and built by the installer, never shipped as binaries. Any new upstream commit makes a toolkit `Behind`, not only a `VERSION` bump. I-24 to I-35 ran against fixture repos in a sandbox; real network clones of the three public repos were exercised only by I-37 (no git credentials were needed). Real Defender or SmartScreen behaviour on the locally built, unsigned executables was not observed.
