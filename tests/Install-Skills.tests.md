# Install-Skills.ps1: test cases

Script: `..\Install-Skills.ps1`. The destination is `%USERPROFILE%\.copilot\skills` (read from `$env:USERPROFILE`) and the repo root is the folder the script sits in. That makes a safe sandbox possible without changing the script: copy `Install-Skills.ps1` into a temporary repo with a few fixture skill folders (each with a `SKILL.md`), set `$env:USERPROFILE` to a temporary folder in the process that runs it, and answer the per-skill prompts by piping `y` or `n` into `powershell -File`. Never run the cases against the real user skills folder. Run 2026-11-01 in such a sandbox (the real skills folder had the same 35 files before and after).

| ID | Setup / action | Expected result | Last result |
| --- | --- | --- | --- |
| I-01 | With an empty isolated destination, run the installer without `-Force` and approve each skill | Each repo subfolder containing `SKILL.md` is listed and copied with its files to the destination; the installer finishes with its completion message | Pass 2026-11-01 (sandbox: two fixture skills installed with y, a folder without SKILL.md was ignored) |
| I-02 | Put an older copy of a skill in the isolated destination, update a source file in the repo, run without `-Force` and approve that skill | The changed file is listed and copied; its installed SHA-256 matches the repo copy afterward | Pass 2026-11-01 (sandbox: the changed file was listed and copied, hashes matched; the untouched skill printed "Already up to date") |
| I-03 | Have multiple skills with changed files; run without `-Force`, decline one skill and approve another | The installer prompts separately for each changed skill; declining leaves that destination unchanged, while approval copies the approved skill and processing continues | Pass 2026-11-01 (sandbox: n left alpha at v1, y installed beta v3; processing continued after the decline) |
| I-04 | Have multiple skills with changed files and run with `-Force` | Copies each changed skill without per-skill confirmation prompts | Pass 2026-11-01 (sandbox: -Force copied alpha with no prompt) |
| I-05 | Edit a file only in an installed skill, then run without `-Force` and approve that skill | The destination hash mismatch is reported as a changed file; approval overwrites the local edit with the repo version | Pass 2026-11-01 (sandbox: the locally edited installed file was reported as changed and overwritten on approval) |
| I-06 | Remove a file from the repo copy of a skill while that file remains in the installed copy, then install the skill without `-Prune` | The installer does not remove destination-only files; it lists them as "no longer in the repo (left in place; use -Prune to remove)" and the removed file remains installed | Pass 2026-11-13 (sandbox: two orphan files were listed and left in place; before `-Prune` existed, 2026-11-01, they were left silently) |
| I-07 | Make an unrelated, uncommitted edit to a file inside a skill folder, then approve installation of that skill | The installer includes the uncommitted repo content; it copies the edited source file without checking Git status | Pass 2026-11-01 (sandbox, in a git repo with `M beta/SKILL.md`: the uncommitted content was installed, the installer does not check git) |
| I-08 | Interrupt a copy to an isolated destination, then rerun the installer with `-Force` | The interrupted run may leave a partial destination; the rerun detects missing/different source files and copies them so installed source files match the repo | Pass 2026-11-01, simulated only (a partial destination was completed by a -Force rerun); a real interruption mid-copy was not tested |
| I-09 | Same setup as I-06, run with `-Prune` and decline the prompt | The orphan files are listed under "File(s) to remove"; declining leaves the destination unchanged | Pass 2026-11-13 (sandbox: n left both orphan files in place) |
| I-10 | Same setup as I-06, run with `-Prune` and approve | The orphan files are deleted, folders left empty by the deletion are removed (a subfolder was), the skill folder and files still in the repo stay; a rerun reports "Already up to date" | Pass 2026-11-13 (sandbox: `scripts\old.ps1` and `scripts\sub\gone.ps1` removed along with the empty `sub` folder; `SKILL.md` and `scripts\keep.ps1` kept; `-Prune -Force` rerun printed "Already up to date") |

## Findings

- Destination-only files are left in place by default and removed only with `-Prune` (added 2026-11-13). Removal is confined to the skill's own destination folder and covered by the per-skill confirmation (skipped with `-Force`). `-Prune -Force` together delete without any prompt; that combination was run only in the sandbox on a rerun with nothing to delete.
