# Learned scripts (agent-orchestrator)

Scripts saved by the orchestrator during supervised runs, next to the core scripts listed in
`../SKILL.md`. Check this table before writing orchestration code. Curated by the user: scripts and
lines are never deleted by the orchestrator.

| Script | Purpose | How to call | Read-only or sends input / modifies | Date |
| --- | --- | --- | --- | --- |
| `Read-CopilotReply.ps1` | Reads Copilot's reply to one prompt: scrolls the chat list to its end (and checks `boundaryReached`), reads all rendered messages, returns only what follows the prompt, plus the completion footer, a `Busy` flag (stop button showing) and `IsClean` (the reply says NO ISSUES REMAIN with no numbered findings). Fixes "no reply yet" reads caused by the virtualized chat list. | `.\Read-CopilotReply.ps1 -Hwnd <h> -AfterPrompt '<phrase from the prompt>'` (without `-AfterPrompt` it uses the last Restore Checkpoint marker) | Read-only apart from the chat list's scroll position; never types or clicks | 2026-10-30 |
| `Invoke-CopilotReview.ps1` | One call for a review loop round: resolves the window (`-TitleContains`, restricted to `devenv`), refuses to send when the chat tab is not showing or the input holds text (so a draft is not cleared), sends the prompt with a unique reference tag via `Send-CopilotPrompt.ps1`, waits with `Wait-CopilotChat.ps1` (default `-Poller Light`; `-Poller Watch` uses `Watch-CopilotChat.ps1`), never answers a permission prompt or question card (returns `NeedsUser` with the question), then returns the reply via `Read-CopilotReply.ps1`. Plays one short beep when the wait ends (`-NoBeep` silences it). `-Review` wraps the prompt in review-only rules and the NO ISSUES REMAIN reply format. | `.\Invoke-CopilotReview.ps1 -TitleContains '<project>' -Review -Prompt '<what to review>'` | Sends a prompt (red-dot cursor via `Send-CopilotPrompt.ps1`); the blue session dot is the caller's | 2026-10-30 |
| `Wait-CopilotChat.ps1` | Light-weight status poller (alternative to `Watch-CopilotChat.ps1`): one in-process UI Automation probe per poll that searches only the input area of the chat pane and never inside the message list's items (it reads only the list's scroll position and its last item). Busy = the stop button (`CancelButton`); waiting = "Allow this time" or a card's "Submit" / "Next question" button; finished = stop button gone plus, only when the list is scrolled to its end, a completion footer as the last item (fallback: a quiet period). Measured on a long chat at a 5 s interval: about 7 % of one core versus about 73 % for the full tree dump, about 0.3 s per probe versus 4.3 s, and no output while polling. Plays one short beep when it ends (`-NoBeep` silences it). Works with the window overlapped or minimized (it never activates, restores, scrolls, clicks or types). Reports `ProbeError` when probes keep failing while the window still exists and `WindowGone` only when the window is really gone. Does not extract question text: call `Watch-CopilotChat.ps1` once for that. `-CrossCheck` compares it with the slow whole-window probe. | `.\Wait-CopilotChat.ps1 -Hwnd <h> -RequireBusyFirst [-PollIntervalSeconds 5] [-TraceFile <path>]` | Read-only for the UI; `-TraceFile` creates or overwrites the file you name | 2026-10-30 |
